# Implementation Gap Matrix: Master Prompt vs. Existing Codebase

**System:** TechMecha Torque Intern Management System (TMT-IMS)  
**Evaluation Scope:** 90 Core Enterprise Requirements from Master Prompt

| Category / Requirement | Prompt Section | Existing Codebase State | Gap Severity | Remediation Strategy |
|---|---|---|---|---|
| **Canonical Lifecycle Continuity** | §1, §17, §18 | Application ➔ Interview ➔ Offer ➔ Intern ➔ Certificate partially linked. No Exit, no Alumni, no Finance links. | 🔴 **CRITICAL** | Introduce unified `Person` model connecting Candidate, User, Intern, and Alumni states with end-to-end auditability. |
| **Finance Subsystem** | §4, §30, §31 | **Completely Missing.** No models, routes, or controllers for stipends, bonuses, deductions, or payment records. | 🔴 **CRITICAL** | Build `Payment`, `PaymentLedger`, and `Compensation` domain module with immutable financial history and state transitions. |
| **Exit / Termination / Offboarding** | §5, §50, §51 | **Completely Missing.** No exit workflow, asset clearance, relieving letter generation, or access revocation. | 🔴 **CRITICAL** | Build `Exit` module with 10-stage offboarding state machine (`EXIT_INITIATED` ➔ `ALUMNI`), asset return, and settlement. |
| **Document Template Engine & TMT Letters** | §6, §7, §71 | Hardcoded PDFKit layout in `pdfGenerator.js`. No template versioning, no dynamic `{{variable}}` substitution. | 🔴 **CRITICAL** | Build dynamic `DocumentTemplate` engine supporting TMT letter templates, versioning (`V1`, `V2`), and variable injection. |
| **Document Preview UI** | §8 | Generic download link only. No desktop/mobile PDF previewer modal with zoom, print, or version diffing. | 🟡 **HIGH** | Implement React PDF previewer modal with zoom, approval controls, and regeneration safeguards. |
| **Storage Architecture & Upload Pipeline** | §9, §10 | Local disk storage only (`uploads/`). No validation pipeline, no temp file cleanup, no Cloudinary adapter. | 🔴 **CRITICAL** | Implement `StorageProvider` abstraction with `LocalStorageProvider` and `CloudinaryStorageProvider` + TTL temp staging. |
| **Environment Configuration & Safety** | §11, §63 | Minimal `.env.example` lacking SMTP, Cloudinary, refresh tokens, and rate limits. No fail-fast validation. | 🟡 **HIGH** | Expand `.env.example` to cover all production variables; add Zod schema validation in `config/env.js` on startup. |
| **SMTP Email System & Idempotency** | §12, §13 | **Completely Missing.** No email service, no Nodemailer, no delivery logs, no event idempotency keys. | 🔴 **CRITICAL** | Implement `EmailService` with Nodemailer, asynchronous worker queue, `EmailLog` collection, and idempotency keys. |
| **Authentication & Refresh Tokens** | §14, §16 | Single JWT token stored in `localStorage`. No refresh token rotation, no session revocation, no logout all devices. | 🔴 **CRITICAL** | Implement short-lived Access Token + HttpOnly Refresh Token in DB `Session` model with device/IP tracking & revocation. |
| **RBAC & Permission Granularity** | §15 | Basic role check (`requireRole`) and wildcard permissions (`ROLE_PERMISSIONS`). Missing granular roles (FINANCE_ADMIN, AUDITOR). | 🟡 **HIGH** | Expand role matrix to 14 enterprise roles with fine-grained scoped permissions and server-side verification. |
| **Recruitment Edge Cases** | §19 | No duplicate application detection, no candidate withdrawal endpoint, no interview reschedule history. | 🟡 **HIGH** | Add duplicate detection (email + openingId), withdrawal state transitions, and interview rescheduling audit trail. |
| **Controlled Offer Workflow** | §20, §72 | Direct transition from Draft to Accepted. Missing HR review, approval workflows, versioning, and expiry tracking. | 🟡 **HIGH** | Implement formal offer workflow (`DRAFT` ➔ `PENDING_APPROVAL` ➔ `APPROVED` ➔ `SENT` ➔ `ACCEPTED`/`EXPIRED`). |
| **Attendance Engine & Policies** | §24 | Hardcoded 10:15 AM late rule. No organization-configurable start time, grace period, or shift rules. | 🟡 **HIGH** | Make attendance policies organization-configurable (`startTime`, `graceMinutes`, `minimumHoursForFullDay`). |
| **Leave Management Subsystem** | §25 | **Completely Missing.** No leave models, balance tracking, or approval workflows. Leaves not tied to attendance. | 🔴 **CRITICAL** | Build `Leave` module with leave types, holiday calendar, approval flow, and integration into daily attendance status. |
| **Task / Sprint Engine** | §26 | Basic task CRUD with PR submission link. Missing epics, sprints, estimated vs. actual hours, and dependencies. | 🟢 **MEDIUM** | Extend Task model with sprint tags, estimated/actual hours, reviewer feedback loops, and deliverable attachments. |
| **Performance Management Cycles** | §27 | Basic mid-term/final rating. Missing self-review step, manager reviews, and immutable post-finalization locks. | 🟢 **MEDIUM** | Add multi-evaluator workflow (Self ➔ Mentor ➔ HR) with post-finalization cryptographic hashing / locking. |
| **Certification Eligibility Engine** | §28, §29 | Manual certificate issuance. Eligibility logic only basic. | 🟡 **HIGH** | Formalize automated rule engine: Attendance ≥ threshold, tasks complete, reviews finalized, finance cleared. |
| **Asset Management** | §49 | **Completely Missing.** No tracking of laptops, monitors, access cards, or company equipment. | 🟡 **HIGH** | Build `Asset` tracking module with lifecycle (`ASSIGNED` ➔ `RETURN_PENDING` ➔ `RETURNED`), tied to Exit Clearance. |
| **Observability & Request Tracing** | §33, §57 | Request ID created in `app.js` but not passed to Winston logger or stored in `AuditLog`. | 🟢 **MEDIUM** | Wire `req.requestId` into all Winston log entries, audit records, and standardized error responses. |
| **Concurrency & Idempotency** | §53, §54 | Offer acceptance checks status, but lack idempotency keys and state transition locks for concurrent requests. | 🟡 **HIGH** | Add optimistic concurrency / state machine validation middleware to reject illegal status transitions. |
| **Testing Suite & Coverage** | §66, §67 | 8 basic API tests in `server/tests/api.test.js`. No unit tests for finance, exits, storage, or email failure. | 🟡 **HIGH** | Expand test suite to include unit tests for state machines, RBAC boundaries, failure scenarios, and transactions. |
